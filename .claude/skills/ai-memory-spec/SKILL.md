# AI 記憶檔規範

## ① 什麼時候用這份說明書

使用者說「幫我建記憶檔」「設定這個專案的規矩」的時候。

**還有一種情況要主動用**：接到一個專案、根目錄沒有 `CLAUDE.md`，
先問他要不要建一份再開始做事。

不適用：他已經有 `CLAUDE.md` 了。那一份是他的規矩，
要改請他自己改，或明確告訴你改哪一條。

## ② 動手前要先問清楚

**一次把四題問完，不要一題一題慢慢來回。** 缺任何一項就先問，不要自己猜。

1. **這個專案是什麼？** 一兩句話，給誰用、做什麼
2. **技術上有什麼是定了的？** 例如「純 HTML 和 CSS，不要框架」「之後要部署到哪」
3. **怎樣算做完了？** 講得出來可以檢查的那種，例如「網址打得開」「手機上不爆版」
4. **有沒有絕對不可以做的事？**

**第 4 題多數人答不出來，那是正常的。** 他說「沒有」或「不知道」的時候，
**不要跳過**，把下面那四條唸給他聽，問他要不要收：

- 不可以把密碼、金鑰寫進程式碼
- 不可以把 `.env` 加進版控
- 不可以用真實的姓名、email、電話當測試資料
- 不可以刪掉他沒要求你改的檔案

他可以刪、可以加，但**這一段不可以是空的**。

## ③ 步驟

1. 問完上面四題，把答案整理成四個區塊，**先唸給他確認再存檔**
2. 存成專案根目錄的 `CLAUDE.md`，四個區塊照這個順序：
   `## 這個專案是什麼`、`## 技術規範`、`## 怎樣算做完了`、`## 絕對不可以做的事`
3. 每一條寫成**一句可以判斷對錯的話**。
   「程式碼要乾淨」不行，「檔名一律小寫，用短橫線分隔」可以
4. 存完告訴他：**這份檔案是每個專案各一份的**，
   換一個專案要再建一次，不要用複製的（那一份講的是上一個專案）
5. 逐項對照下方「做完要檢查」，把結果列出來給他看

## ④ 產出格式

```
CLAUDE.md           放在專案根目錄（跟 index.html 同一層）
```

四個區塊，用 `##` 當小標，每一條一行，開頭用 `- `。

## ⑤ 做完要檢查

逐項回報通過與否，**不要只說「已完成」**。

- `CLAUDE.md` 在專案根目錄，不是在子資料夾裡
- 四個區塊都在，而且**「絕對不可以做的事」那一塊不是空的**
- 每一條都判斷得出對錯，沒有「要乾淨」「要好用」這種形容詞
- 裡面寫的是**這一個**專案，不是上一個專案的內容
- 沒有任何真實的姓名、email、電話、金鑰

## ⑥ 禁止事項

- **不可以自己幫他決定規矩然後直接寫進去。** 四題都要問過。
  他答不出來的那一題，你給選項讓他挑，不是替他挑
- **不可以把金鑰、密碼、token 寫進 `CLAUDE.md`。**
  那份檔案會進版控，會上 GitHub
- 不可以用真實的姓名、email、電話當範例
- 不可以覆蓋已經存在的 `CLAUDE.md` —— 先讀它，問他要改哪一條
- 不可以把「絕對不可以做的事」那一段留空或寫「無」
